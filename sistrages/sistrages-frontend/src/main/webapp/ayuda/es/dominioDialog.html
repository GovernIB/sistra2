MANTENIMIENTO DOMINIO

En la pantalla de 'Mantenimiento dominio' puede mantener los datos correspondientes a un dominio.
Los campos obligatorios se presentan con un asterisco *.

CAMPOS

  • Identificador: código unívoco que identifica al dominio dentro de la aplicación. Este identificador se utilizará en cualquier script de la aplicación para acceder al dominio
  • Descripción: texto descriptivo del objeto del dominio.
  • Configuración cacheo: desplegable que permite seleccionar entre 3 tipos de cacheo:
    • Caché habilitada: indica que el dominio es cacheable y se mantendrán los datos durante 24 horas. En caso de querer forzar a refrescar los datos, se puede invalidar la caché para el dominio.
    • Caché deshabilitada (cacheo implícito): indica que el dominio no es cacheable, pero existirá un cacheo implícito durante 1 minuto para evitar repeticiones de llamadas a dominios, para mejorar el rendimiento (sobre todo en carga de formularios en los cuales se alimenten diversos campos en función de un dominio). Esta opción habrá de ser la que se use por defecto cuando no es quiere cachear un dominio.
    • Caché deshabilitada: indica que el dominio no es cacheable y en cada invocación se fuerza a invocar a un dominio. Esta opción se deberá usar cuando se quiere forzar cuando se requiere que cada llamada a dominio fuerce la invocación al mismo (p. ej.: dominio que realice un insert en BBDD).
  • Tipo: Tipología del dominio, que puede ser Consulta BBDD, Lista Fija, Consulta Remota o Fuente Datos, esta última no disponible en dominios de ámbito global. Según el tipo de dominio se tendrá que configurar:
    • Consulta BBDD: dominio que consulta datos de una base de datos:
      • JNDI Datasource: ha de contener el JNDI del datasource que contiene la BBDD que consultará el dominio. Se ha de tener en cuenta que este datasource ha de estar desplegado en el mismo servidor de aplicaciones que SISTRAGESBACK.
      • Query: consulta, en lenguaje SQL, a ejecutar sobre la BBDD indicada en el datasource. En caso de que la consulta requiera parámetros, estos se referenciarán mediante su código y precedido por el símbolo dos puntos (:). A continuación se presenta un ejemplo ilustrativo de una consulta con un parámetro identificador:

        SELECT ID, DESC1, DESC2 FROM TAULA WHERE ID = :identificador
    • Lista fija: dominio que recupera datos de una lista fija de valores. El mantenimiento del listado de valores permite las operaciones siguientes:
      • Nuevo: permite crear un nuevo elemento en el listado. Este elemento consta del código del elemento y del valor del mismo
      • Editar: permite editar un elemento ya existente en el listado. Antes de pulsar el botón de edición tendrá que seleccionar en el listado el elemento a editar.
      • Eliminar: permite eliminar un elemento existente en el listado. Antes de hacer clic en el botón de eliminación se ha de seleccionar en el listado el elemento a eliminar.
      • Subir: permite subir un elemento en el orden del listado. Para subir un elemento previamente ha de estar seleccionado en el listado.
      • Bajar: permite bajar un elemento en el orden del listado. Para subir un elemento previamente ha de estar seleccionado en el listado.
    • Consulta Remota: dominio que recupera valores de una ubicación remota a partir del plug-in de dominio remoto:
      • URL: URL contra la que se hará la consulta remota. Si existe un placeholder (por haber seleccionado una variable de área), este será sustituido por el contenido de esa variable, que será insertado al comienzo de este campo. Por ejemplo, si en la variable VAR01 aparece la URL “https://se.caib.es” y la URL de este campo ha de finalizar con “proyectoBase/services/dominios/”, en este campo aparecerá el texto “{@@VAR01@@}/proyectoBase/services/dominios/”.
      • Selección Variable Área: Este botón abre una pantalla que permite seleccionar una variable de área que añadirá un placeholder que será sustituido por la URL indicada en esa variable de área a la hora de ejecutar el trámite que utilice este dominio.
      • Para consultar como definir dominios SOAP (utilizados en SISTRA1) y REST (utilizados en SISTRA2), clicad aquí
    • Fuente Datos: dominio que recupera datos de una Fuente de Datos definida en SISTRAGESBACK:
      • Fuente: desplegable que permite seleccionar la fuente de datos a consultar. Únicamente se muestran las fuentes de datos que pertenecen al ámbito del dominio
      • Query: consulta, en lenguaje pseudoSQL para consultar una fuente de datos. El formato de esta consulta tiene que ser:

        SELECT campo (, campo)* FROM fuenteDatos WHERE expresion ( [AND | OR] expresion ] )* ORDER BY campo

        donde expresion: campo [= | LIKE]:param, donde ":param” equivale al parámetro que se pasará

        Las partículas de la sentencia pseudoSQL (SELECT, FROM, WHERE, LIKE, AND, OR, ORDER BY) han de estar en mayúsculas.
        Respecto a las comparanciones en el WHERE serán ignorecase ( = y LIKE ).
        Respecto al LIKE se realizará automáticamente la comparació.
        Respecto al ORDER BY solo se puede indicar un campo. Además, como todos los campos son de tipo cadena, la ordenación es literal, por lo que si se quiere crear un campo en la fuente de datos que permita ordenar secuencialmente, mejor utilizar letras que números.

  • Parámetros: listado de parámetros del dominio. Las operaciones que se pueden realizar sobre este listado son:
    • Nuevo: permite crear un parámetro. Este parámetro se identifica a partir de un código.
    • Editar: permite editar un parámetro ya existente en el listado. Antes de pulsar el botón de edición tendrá que seleccionar el parámetro a editar en el listado.
    • Eliminar: permite eliminar un parámetro existente en el listado. Antes de pulsar el botón de eliminación tendrá que seleccionar el parámetro a eliminar en el listado.
    • Subir: permite subir un parámetro en el orden del listado de parámetros. Para subir un parámetro previamente ha de estar seleccionado en el listado de parámetros.
    • Bajar: permite bajar un parámetro en el orden del listado de parámetros. Para bajar un parámetro previamente ha de estar seleccionado en el listado de parámetros.

OPERATIVA

  • Guardar: cierra la pantalla guardando los cambios.
  • Cancelar: cierra la pantalla sin guardar los cambios.
